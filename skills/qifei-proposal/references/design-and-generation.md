# 设计系统与合同式生成

## 品牌官方视觉审计

提出视觉方向前，先读取 `inputs/brand-official/` 和 `evidence/brand-visual-audit.md`。至少提取并标注来源 ID：

- 品牌识别符号、Logo 使用与安全区。
- 官方色卡；若资料未给色值，只能标为“从官方画面采样”，记录采样文件和位置。
- 官方字体或可核验的字体特征；不得凭截图猜测具体字体名称。
- 图形母题、线条、容器、纹理、材质、光影和空间关系。
- 官方摄影、人物、产品、场景、构图和后期特征。
- 版式节奏、信息密度、动效倾向和明确禁忌。

把事实分成 `official_explicit`、`sampled_from_official`、`proposal_choice` 三类。前两类来自品牌资料；第三类是本案设计决策，不能包装为官方规范。

### 品牌层与产品层

品牌视觉审计必须拆成两个相互协作的层级：

1. **企业品牌识别层**：官方 Wordmark/Logo、核心品牌色、识别性图形与品牌 DNA，负责回答“这是谁的方案”。
2. **产品/品类气质层**：产品颜色、材质、消费人群、使用场景与品类情绪，负责回答“这是什么产品、服务谁”。

产品图不能替代品牌官方视觉输入，产品色也不能自动升级为全案品牌色。审计需要为两层分别记录来源、作用和允许占比，并定义 `brand_presence: light | medium | strong`。产品运营、品类策略与女性/生活方式提案默认从 `light` 起步，除非 Proposal Owner 或官方资料要求更强介入。

`light` 代表最低充分品牌识别，不代表品牌缺席。至少保留：

- 一个稳定、准确的官方品牌标识及安全区。
- 核心品牌色承担明确的识别或结构功能，可作为线条、路径、关键节点或局部背景，不要求大面积铺色。
- 一种来自品牌 DNA 的视觉语法，例如精确秩序、工程结构、人本科技或特定摄影特征；不得用通用粒子、霓虹和科幻装饰代替。
- 产品/品类色继续承担页面温度、材质和消费情绪，不被企业品牌色粗暴覆盖。

品牌校准以“可识别且不压过内容主角”为合格标准。品牌 DNA 的转译强度必须服从项目主题、受众、品类气质、页面任务和已确认的视觉命题；不得把任何单一品牌特征机械放大为全案风格。

## 设计语言校准集

初始方向样张只负责选方向。方向确认后创建独立 `deck/design-calibration.html`，用真实或等密度的冻结内容验证整套设计语言。校准集必须包含 `data-design-sample` 标记：

- `cover`：首页。
- `toc`：目录页。
- `chapter-type-led`、`chapter-image-led`、`chapter-data-led`：至少 3 种同源章节页变体。
- `content-low`、`content-medium`、`content-high`：低/中/高密度正文页；可增加观点、图文、框架、数据、案例和工作件样张。
- `content-visual-module`：至少一页验证“HTML 内容模板 + 透明 PNG 高表现力模块”的叠加关系。
- `closing`：结尾感谢页。

使用 Codex 浏览器原生评论逐页修订。确认对象包括：品牌识别、字体层级、网格、安全区、色彩、材质、组件、内容密度和页间节奏。全部样张关闭评论后记录 `design_calibration` 批准；不得用一张封面或一张内容页推断整套设计系统。

## DESIGN.md

样张确认后生成 `DESIGN.md`，至少定义：

- 客户品牌与本案视觉命题。
- 品牌官方视觉资料的来源 ID、文件、核准范围和提取结论。
- 品牌视觉符号、Logo 规则、官方/采样色卡、字体依据及本案融合方式。
- 企业品牌层与产品/品类层的职责分配、`brand_presence` 强度、最低品牌锚点及其页面位置。
- 画布固定为 1920x1080，16:9。
- 色彩、字体、字号层级、行距和安全区。
- 背景、光影、材质、图形语言和摄影/生成图风格。
- 首页、目录页、至少 3 种同源章节页、观点页、数据页、框架页、案例页、工作件页、视觉 Demo 页和结尾感谢页的构图规则。
- 图表、表格、数字、来源和页码规范。
- Image2 使用范围、禁用范围和透明 PNG 资产规范。
- 透明 PNG 图层槽位：允许出现的页面族、画布比例、锚点、最大边界、层级、遮挡保护区、最小分辨率和替代方案。
- 页面密度等级与拆页规则。
- 固定设计语言与正文页弹性合同：列明不可变项、可变项、密度等级、可选布局族、媒体槽位和拆页触发条件。
- 按章节生成、局部重建和设计版本失效规则。
- 明确的视觉禁忌和样张版本。

`DESIGN.md` 必须逐项说明“继承什么、转译什么、本案新增什么”。全部 `brand_visual.source_ids` 都必须在文件中出现。来源缺失、色值类别混淆或品牌符号未落入设计令牌时，不得批准设计系统。

`DESIGN.md` 是视觉权威；`deck/design-tokens.json` 是其机器可读编译产物，不可反向覆盖 `DESIGN.md`。

### 固定与弹性的边界

固定首页、目录页、章节页和结尾感谢页的核心构图与识别方式。正文内容页不要锁死为单一母版；只冻结：

- 品牌符号、Logo 规则、色卡、字体体系和图形/材质语言。
- 画布、安全区、基础网格、间距尺度、组件语法和最小字号。
- 数据、图表、来源、页码和媒体适配规则。
- 低/中/高密度上限及必须拆页的条件。

正文页可根据内容在合同内调整：列数、模块组合、媒体比例、留白、强调方式和内容族。变化必须来自内容任务，不能为了“每页不同”而随机换风格。

### HTML 内容模板与透明 PNG 模块

把正文页拆成可组合的三层：

1. **HTML 结构层**：标题、正文、数字、图表、注释、网格和可编辑信息组件。
2. **透明 PNG 表现层**：HTML 难以完成的产品特写、空间装置、概念造型、粒子、材质、3D 元素和高表现力视觉模块。
3. **背景/场景层**：全幅氛围、摄影场景或生成背景；需要时使用，不是每页必需。

先选定内容页模板和视觉槽位，再生成透明 PNG；不得让生成图决定或改写内容结构。每个透明模块必须记录：

- 目标 `slide_id`、槽位 ID、用途和视觉结论。
- 透明背景要求、宽高比、最小像素尺寸、主体边界和安全留白。
- HTML 锚点、`z-index`、最大占位、允许出血和禁止遮挡区域。
- 品牌色、光向、材质、视角和与页面背景的融合要求。
- Prompt 版本、来源/参考 ID、批准状态和替代资产。

正式文件使用带真实 Alpha 通道的 PNG，不接受把黑底、白底或棋盘格烘焙进图片。透明模块不得包含正文、图表标签、关键数字或未核准 Logo。视觉 QA 必须检查透明通道、白边/黑边、锯齿、脏像素、裁切、清晰度、缩放和遮挡关系。

## deck-spec.json

内容冻结后生成。顶层至少包含：

- `deck_id`、`project_name`
- `content_freeze_id`
- `design_version`
- `source_hashes`
- `slides`

每页至少包含：

- `slide_id`、`chapter`、`role`、`layout`
- `title`、`subtitle`、`kicker`
- `blocks`
- `visual`
- `evidence_ids`
- `speaker_doc_anchor`
- `status: content_frozen`
- `approved_content_hash`

主标题承担页面判断，不以中英文句号收尾；副标题、正文、来源与图注不受此限制。

## 页面合同

`slide-contracts.json` 为每种 `layout` 定义：

- 标题、副标题和正文最大视觉字符宽度。
- 列表、卡片、数字和流程步骤最大数量。
- 媒体槽位数量、比例和适配方式。
- 必填字段与允许为空字段。
- 最小字号和建议密度。

字符预算按全角 1、半角 0.5 做预检；最终用浏览器测量 `scrollWidth/clientWidth`、`scrollHeight/clientHeight`、页面边界和元素相交。

### 页面生产路由

在调用 Image2 或编写 HTML 前，为每页写入 `presentation_route`。它不是设计说明书，而是防止 Agent 先套版、后硬塞信息的生产门禁。至少记录：

- 服务对象、使用情境、演讲任务和内容关系。
- 表达对象（数据证据、比较、趋势、流程、系统、场景、机制、工作件或主张）与最佳载体。
- 唯一主导类型：`information_first` 或 `design_first`。
- 视觉论点：第一眼主对象、阅读路径、最终视觉落点。
- 视觉锤：唯一的第一视觉对象；标题、时间线、标签和辅助图形如何服务它；逐项排查孤儿数字、白底标签、重复口号和装饰元素，不能服务主对象时删除、并入或图形化。
- 当产品是场景主对象时，优先以官方产品参考让 Image2 把产品融入同一光源、透视和接触阴影；HTML/真实包装层仅用于精确校正或近景证据，不得成为场景中的白底贴图或悬浮卡。
- Image2 决策：明确记录本页是否生成、资产承担的语义角色（场景、主视觉、机制、无文字语义图标、透明表现模块或不使用）、生成理由，以及必须由 HTML 保护的精确内容。无文字语义图标可表达内容、商品、人群、场景或增长信号等稳定节点；只有它服务流程、系统或关系图的阅读路径时才生成。
- 主视觉锚点由 HTML、Image2 或二者共同承担；流程、系统、场景、机制和工作件页必须有清晰可见的主载体。
- Image2 和 HTML 的分工，以及文字、主载体、辅助元素的视觉重量计划。

`visual_mode: none` 只允许用于由 HTML 自身承担可见主载体的精确数据、比较或趋势页。它不能用来把流程、直播现场、经营系统、产品机制或工作件退化成卡片和文字清单。视觉 QA 必须检查“视觉论点与视觉锤已实现、远距可读、空白和视觉重量平衡”，不只检查溢出。

## Image2

只用于：

- 背景与主视觉。
- 客户定制场景图。
- 概念图、科技可视化和高表现力视觉模块。
- 无文字的语义图标，用于把内容、商品、人群、场景或增长信号转成一眼可识别的节点；图标要并入主关系，不能成为孤儿装饰。
- 经批准的透明 PNG 核心元素与内容模板图层模块。

不用 Image2 生成正文、数据表、图表标签或大段文字；也不用它承载需要严密核对的多步逻辑关系、精确数据或不可核验标签。此类内容由 HTML 的表格、图表、时间线、流程或关系标注承担。提示词必须去标识化；模型不可用时输出提示词包。

项目生成资产放入 `assets/image2/`，经人工批准后移动到 `assets/approved/`。只有去标识化并获批的资产可提升到公司通用素材库。

透明模块优先使用 `assets/image2/alpha/`，批准后进入 `assets/approved/alpha/`。页面合同把这类媒体标记为 `transparent: true`；生成校验必须确认文件为 PNG 且存在 Alpha 通道。

## HTML 母版

- 所有正文、数据、图表和图注由 HTML 排版。
- 每页使用 `.slide[data-slide-id]`，尺寸固定 1920x1080。
- HTML 不内置评论侧栏或评论存储；评审使用 Codex 浏览器原生评论功能。
- 修订发生在章节源稿、`deck-spec.json` 或 `DESIGN.md`，之后重建 HTML。
- `build-manifest.json` 记录内容、设计和资产哈希；任一上游变化都使旧导出过期。
- 按章节评审时输出 `deck/chapters/<chapter_id>.html`；最终输出仍为 `deck/proposal.html`。章节输出只用于提速和评审，不替代全案构建。
- 章节评论循环同步输出 `deck/review/<chapter_id>/<slide_id>.png`；此阶段不生成 PDF 或 PPT。

## Codex 浏览器评论

- 在 Codex 浏览器中打开 `deck/proposal.html`，直接使用浏览器原生评论功能标注页面。
- 评论应指出 `slide_id`、问题和期望修改；页面本身持续显示稳定 `slide_id` 供定位。
- Agent 读取评论后修改上游权威文件，再重新校验、渲染章节 HTML 和评审 PNG；不得在每轮修改后重复拼装 PPT/PDF。
- 不为评论额外维护侧边栏、API、本地服务或项目内评论 JSON。
- 评论不能直接修改冻结内容；涉及内容变更时仍按页面重开与重新冻结规则执行。

## 页面确认与拼装准备

- 评论全部解决不等于页面确认。只有 Proposal Owner 的明确确认命令才改变页面状态。
- `deck/review/` 保存循环中的 HTML 对应 PNG 与评审清单；它们可以反复覆盖，不属于最终交付。
- `deck/assembly-ready/` 保存已经明确确认的逐页 PNG 和 `manifest.json`；每页必须绑定批准内容哈希、内容冻结 ID、设计版本和确认记录。
- 页面重开后立即撤回对应 ready 条目；设计系统改变时全部 ready 条目失效。
- 全部正式页面 ready 且 Owner 批准最终拼装前，不得生成全案 PDF/PPT。

## 双轴 QA

### 内容 QA

- HTML 与冻结内容逐字段一致。
- 标题、数字、证据、讲稿锚点和页序一致。
- 策略与上屏文字无高频公式句式、模糊归因和空泛宣传；页面演讲任务与画面一致。完整讲稿在全部PPT页面和最终页序确认后另行生成与朗读，不作为前期视觉生成门禁。
- 没有新增结论、承诺或未确认文案。
- 没有公司介绍侵入客户策略。
- 没有内部备注、绝对路径、占位符或敏感信息。

### 视觉 QA

- 无溢出、裁切、重叠、黑块、缺图和字体替换。
- 透明 PNG 无黑底/白底、白边、黑边、脏像素、错误遮挡或低分辨率放大。
- 视觉层级、对齐、安全区、字号和来源可读。
- Image2 资产与 HTML 文字风格一致。
- 相邻页面节奏有变化但属于同一设计系统。
- 品牌归属测试通过：遮住产品后，核心页面仍保留适度品牌识别；把品牌标识和产品替换成竞品后，画面不能仍然完全成立。
- 品牌介入强度符合 `DESIGN.md`：品牌色和科技 DNA 提供识别与秩序，不挤压产品色、品类情绪和页面结论。
- 逐页 PNG 与 HTML 完全一致。

## 导出

只在全部页面进入拼装准备库、全案 QA 通过且 Owner 明确批准最终拼装后导出：

- `deck/proposal.html`
- `exports/png/<slide_id>.png`
- `exports/proposal.pdf`
- `exports/proposal-preview.pptx`

PPT 每页只放一张经确认的 16:9 全页 PNG，是预览件而非可编辑母版。最终 PNG、PDF 和 PPT 按 `deck-spec.json` 页序一次性拼装；修订不得发生在 PPT 中，评审循环也不得重复生成 PPT。
