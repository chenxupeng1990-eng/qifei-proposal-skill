# 设计系统与合同式生成

## 品牌官方视觉审计

提出视觉方向前，先读取 `inputs/brand-official/` 和 `evidence/brand-visual-audit.md`。至少提取并标注来源 ID：

- 品牌识别符号、Logo 使用与安全区。
- 官方色卡；若资料未给色值，只能标为“从官方画面采样”，记录采样文件和位置。
- 官方字体或可核验的字体特征；不得凭截图猜测具体字体名称。
- 图形母题、线条、容器、纹理、材质、光影和空间关系。
- 官方摄影、人物、产品、场景、构图和后期特征。
- 版式节奏、信息密度、动效倾向和明确禁忌。

把事实分成 `official_explicit`、`sampled_from_official`、`proposal_choice` 三类。前两类来自品牌资料；第三类是本案设计决策，不能包装为官方规范。

## 设计语言校准集

初始方向样张只负责选方向。方向确认后创建独立 `deck/design-calibration.html`，用真实或等密度的冻结内容验证整套设计语言。校准集必须包含 `data-design-sample` 标记：

- `cover`：首页。
- `toc`：目录页。
- `chapter-type-led`、`chapter-image-led`、`chapter-data-led`：至少 3 种同源章节页变体。
- `content-low`、`content-medium`、`content-high`：低/中/高密度正文页；可增加观点、图文、框架、数据、案例和工作件样张。
- `content-visual-module`：至少一页验证“HTML 内容模板 + 透明 PNG 高表现力模块”的叠加关系。
- `closing`：结尾感谢页。

使用 Codex 浏览器原生评论逐页修订。确认对象包括：品牌识别、字体层级、网格、安全区、色彩、材质、组件、内容密度和页间节奏。全部样张关闭评论后记录 `design_calibration` 批准；不得用一张封面或一张内容页推断整套设计系统。

## DESIGN.md

样张确认后生成 `DESIGN.md`，至少定义：

- 客户品牌与本案视觉命题。
- 品牌官方视觉资料的来源 ID、文件、核准范围和提取结论。
- 品牌视觉符号、Logo 规则、官方/采样色卡、字体依据及本案融合方式。
- 画布固定为 1920x1080，16:9。
- 色彩、字体、字号层级、行距和安全区。
- 背景、光影、材质、图形语言和摄影/生成图风格。
- 首页、目录页、至少 3 种同源章节页、观点页、数据页、框架页、案例页、工作件页、视觉 Demo 页和结尾感谢页的构图规则。
- 图表、表格、数字、来源和页码规范。
- Image2 使用范围、禁用范围和透明 PNG 资产规范。
- 透明 PNG 图层槽位：允许出现的页面族、画布比例、锚点、最大边界、层级、遮挡保护区、最小分辨率和替代方案。
- 页面密度等级与拆页规则。
- 固定设计语言与正文页弹性合同：列明不可变项、可变项、密度等级、可选布局族、媒体槽位和拆页触发条件。
- 按章节生成、局部重建和设计版本失效规则。
- 明确的视觉禁忌和样张版本。

`DESIGN.md` 必须逐项说明“继承什么、转译什么、本案新增什么”。全部 `brand_visual.source_ids` 都必须在文件中出现。来源缺失、色值类别混淆或品牌符号未落入设计令牌时，不得批准设计系统。

`DESIGN.md` 是视觉权威；`deck/design-tokens.json` 是其机器可读编译产物，不可反向覆盖 `DESIGN.md`。

### 固定与弹性的边界

固定首页、目录页、章节页和结尾感谢页的核心构图与识别方式。正文内容页不要锁死为单一母版；只冻结：

- 品牌符号、Logo 规则、色卡、字体体系和图形/材质语言。
- 画布、安全区、基础网格、间距尺度、组件语法和最小字号。
- 数据、图表、来源、页码和媒体适配规则。
- 低/中/高密度上限及必须拆页的条件。

正文页可根据内容在合同内调整：列数、模块组合、媒体比例、留白、强调方式和内容族。变化必须来自内容任务，不能为了“每页不同”而随机换风格。

### HTML 内容模板与透明 PNG 模块

把正文页拆成可组合的三层：

1. **HTML 结构层**：标题、正文、数字、图表、注释、网格和可编辑信息组件。
2. **透明 PNG 表现层**：HTML 难以完成的产品特写、空间装置、概念造型、粒子、材质、3D 元素和高表现力视觉模块。
3. **背景/场景层**：全幅氛围、摄影场景或生成背景；需要时使用，不是每页必需。

先选定内容页模板和视觉槽位，再生成透明 PNG；不得让生成图决定或改写内容结构。每个透明模块必须记录：

- 目标 `slide_id`、槽位 ID、用途和视觉结论。
- 透明背景要求、宽高比、最小像素尺寸、主体边界和安全留白。
- HTML 锚点、`z-index`、最大占位、允许出血和禁止遮挡区域。
- 品牌色、光向、材质、视角和与页面背景的融合要求。
- Prompt 版本、来源/参考 ID、批准状态和替代资产。

正式文件使用带真实 Alpha 通道的 PNG，不接受把黑底、白底或棋盘格烘焙进图片。透明模块不得包含正文、图表标签、关键数字或未核准 Logo。视觉 QA 必须检查透明通道、白边/黑边、锯齿、脏像素、裁切、清晰度、缩放和遮挡关系。

## deck-spec.json

内容冻结后生成。顶层至少包含：

- `deck_id`、`project_name`
- `content_freeze_id`
- `design_version`
- `source_hashes`
- `slides`

每页至少包含：

- `slide_id`、`chapter`、`role`、`layout`
- `title`、`subtitle`、`kicker`
- `blocks`
- `visual`
- `evidence_ids`
- `speaker_doc_anchor`
- `status: content_frozen`
- `approved_content_hash`

## 页面合同

`slide-contracts.json` 为每种 `layout` 定义：

- 标题、副标题和正文最大视觉字符宽度。
- 列表、卡片、数字和流程步骤最大数量。
- 媒体槽位数量、比例和适配方式。
- 必填字段与允许为空字段。
- 最小字号和建议密度。

字符预算按全角 1、半角 0.5 做预检；最终用浏览器测量 `scrollWidth/clientWidth`、`scrollHeight/clientHeight`、页面边界和元素相交。

## Image2

只用于：

- 背景与主视觉。
- 客户定制场景图。
- 概念图、科技可视化和高表现力视觉模块。
- 经批准的透明 PNG 核心元素与内容模板图层模块。

不用 Image2 生成正文、数据表、图表标签或大段文字。提示词必须去标识化；模型不可用时输出提示词包。

项目生成资产放入 `assets/image2/`，经人工批准后移动到 `assets/approved/`。只有去标识化并获批的资产可提升到公司通用素材库。

透明模块优先使用 `assets/image2/alpha/`，批准后进入 `assets/approved/alpha/`。页面合同把这类媒体标记为 `transparent: true`；生成校验必须确认文件为 PNG 且存在 Alpha 通道。

## HTML 母版

- 所有正文、数据、图表和图注由 HTML 排版。
- 每页使用 `.slide[data-slide-id]`，尺寸固定 1920x1080。
- HTML 不内置评论侧栏或评论存储；评审使用 Codex 浏览器原生评论功能。
- 修订发生在章节源稿、`deck-spec.json` 或 `DESIGN.md`，之后重建 HTML。
- `build-manifest.json` 记录内容、设计和资产哈希；任一上游变化都使旧导出过期。
- 按章节评审时输出 `deck/chapters/<chapter_id>.html`；最终输出仍为 `deck/proposal.html`。章节输出只用于提速和评审，不替代全案构建。

## Codex 浏览器评论

- 在 Codex 浏览器中打开 `deck/proposal.html`，直接使用浏览器原生评论功能标注页面。
- 评论应指出 `slide_id`、问题和期望修改；页面本身持续显示稳定 `slide_id` 供定位。
- Agent 读取评论后修改上游权威文件，再重新校验、渲染和导出。
- 不为评论额外维护侧边栏、API、本地服务或项目内评论 JSON。
- 评论不能直接修改冻结内容；涉及内容变更时仍按页面重开与重新冻结规则执行。

## 双轴 QA

### 内容 QA

- HTML 与冻结内容逐字段一致。
- 标题、数字、证据、讲稿锚点和页序一致。
- 没有新增结论、承诺或未确认文案。
- 没有公司介绍侵入客户策略。
- 没有内部备注、绝对路径、占位符或敏感信息。

### 视觉 QA

- 无溢出、裁切、重叠、黑块、缺图和字体替换。
- 透明 PNG 无黑底/白底、白边、黑边、脏像素、错误遮挡或低分辨率放大。
- 视觉层级、对齐、安全区、字号和来源可读。
- Image2 资产与 HTML 文字风格一致。
- 相邻页面节奏有变化但属于同一设计系统。
- 逐页 PNG 与 HTML 完全一致。

## 导出

只从通过 QA 的 HTML 导出：

- `deck/proposal.html`
- `exports/png/<slide_id>.png`
- `exports/proposal.pdf`
- `exports/proposal-preview.pptx`

PPT 每页只放一张 16:9 全页 PNG，是预览件而非可编辑母版。修订不得发生在 PPT 中。
