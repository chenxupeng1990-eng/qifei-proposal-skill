# 逐页内容与飞书演讲稿

## 页面确认卡

每一页在用户确认前至少包含：

- `slide_id`
- 章节与页面角色
- 结论式标题
- 上屏副标题/正文/数字/图注
- 本页证据及来源
- 页面要回答的问题
- 页面与前后页的推导关系
- 页面语义角色、当前新增的理解和下一页产生的必要性
- 视觉意图，不等于最终设计
- 演讲任务和逐页讲稿
- 需要用户确认的唯一争议点

结构和关键创意不等于页面内容确认。不得用目录确认代替逐页确认。

页面与章节的跨页语义字段、重复元素判断和全案复核方式见 [cross-page-semantic-qa.md](cross-page-semantic-qa.md)。同一结论换词复述不算推进；标题句式、视觉母题、人物和版式重复只有在承担新语义时才成立。

策略、上屏文案和讲稿的自然表达规则见 [writing-style-and-humanization.md](writing-style-and-humanization.md)。去除 AI 痕迹发生在事实、逻辑和策略确认之后，不得为了口语化改变口径。

## 演讲稿

演讲稿以飞书文稿为团队协作母版。每页使用稳定 `slide_id` 作为标题锚点：

```text
[P12] 页面标题
演讲任务：评审听完后应得出什么结论
建议时长：60-90 秒
讲稿：...
转场：如何进入 P13
可能追问：...
回答要点：...
```

HTML 不承载完整演讲稿，只保留 `speaker_doc_anchor`。飞书不可用时，先写入 `content/speaker-notes.md`，之后按 `slide_id` 同步。

讲稿初稿完成后必须逐页朗读。讲稿负责解释意义和推动下一页，不逐字复述标题、卡片和表格；如果读起来像报告摘要、广告旁白或由连接词拼接的长句，返回重写。

## 页级信息规则

- 一页一个核心结论，不用缩字承载两个完整任务。
- 方法论和完整样例通常拆页。
- 一个完整脚本、工作件、场景 Demo 或复杂时间系统优先独占一页。
- 标题表达判断，不写“市场分析”“执行规划”等空泛名词。
- 主标题不以中英文句号收尾，保持提案标题的判断感与视觉收束；正文、图注、来源和表格说明可正常使用标点。
- 数据必须给出时间、口径和内部证据编号；外部页脚只展示必要短来源。
- 对外不写 `待确认`、`内部使用`、`需法务确认`、Agent 名称或版本治理规则。

## 冻结

页面确认后记录确认人、时间和确认记录 ID。全案对抗检测通过后，由 Owner 生成内容冻结 ID。`freeze_deck_spec.py` 为每页写入批准内容哈希；任何上屏文案、证据、视觉意图或讲稿锚点改变都会使该页过期。

内容确认与视觉成稿确认是两道不同门禁。视觉评论循环中，评论已处理不等于页面成稿确认；只有 Proposal Owner 明确确认对应 `slide_id` 后，该页 HTML 对应的 PNG 才能进入 `deck/assembly-ready/`。最终 PPT/PDF 在全部正式页面确认后一次性拼装。
