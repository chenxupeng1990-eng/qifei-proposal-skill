# PPT提案成稿与最终飞书演讲稿

## 生产粒度与协作载体

先确认章节策略接口、页面论证链和只读标题链，再一次性生成整章全部PPT页面正文。逐页是审阅、评论和确认粒度，不是默认生成粒度。完整讲稿不得在此阶段生成。

整章批量成稿必须：

- 使用同一份已确认策略输入、标题链和术语表；
- 同时写出所有页面的上屏内容、证据、演讲任务、视觉意图和说服力字段；
- 完成后连续阅读整章，检查前提、判断、证据、情绪和转场；
- 不在生成正文时静默修改页序或章节命题；
- 只有完整脚本、关键创意或争议页需要深挖时，才单独生成该页。

飞书PPT提案成稿是内容阶段的默认协作母版：

1. 一个项目使用一份主提案文档，不为每章创建分散文档。
2. 章节整批写入，页面以稳定 `slide_id` 标题作为评论锚点。
3. 团队在飞书逐页评论；Agent 读取新增评论后，修改对应页面及必要转场。
4. 每轮写入后回读章节标题、首尾页和 revision，确认真实落文档。
5. 评论解决不等于页面确认；Owner 明确确认后才记录页面状态。
6. 本地 `content/chapters/` 保存同步稿与审计记录；飞书不可用时先写本地，恢复后按 `slide_id` 同步。
7. 此阶段只保留“演讲任务”，不得把任务扩写成完整讲稿。

具体页面字段、飞书层级和视觉建议格式见 [feishu-proposal-draft-format.md](feishu-proposal-draft-format.md)。其中“讲解方向”是页面说明，不是最终逐字讲稿。

## 页面确认卡

每一页在用户确认前至少包含：

- `slide_id`
- 章节与页面角色
- 结论式标题
- 上屏副标题/正文/数字/图注
- 本页证据及来源
- 页面要回答的问题
- `belief_shift`：客户看完后需要发生的认知变化
- `emotional_target`：本页需要触发的情绪
- `decisive_judgment`：本页作出的鲜明判断
- `visible_proof`：使判断成立的事实、内容原型或执行工作件
- `next_tension`：引向下一页的问题、期待或未完成动作
- 页面与前后页的推导关系
- 页面语义角色、当前新增的理解和下一页产生的必要性
- 视觉意图，不等于最终设计
- 演讲任务；完整逐页讲稿后置到最终PPT确认之后
- 需要用户确认的唯一争议点

结构和关键创意不等于页面内容确认。不得用目录或整章批量生成代替逐页确认。

页面与章节的跨页语义字段、重复元素判断和全案复核方式见 [cross-page-semantic-qa.md](cross-page-semantic-qa.md)。同一结论换词复述不算推进；标题句式、视觉母题、人物和版式重复只有在承担新语义时才成立。

策略和上屏文案的自然表达规则见 [writing-style-and-humanization.md](writing-style-and-humanization.md)。去除 AI 痕迹发生在事实、逻辑和策略确认之后，不得为了口语化改变口径。

## 最终演讲稿

### 生成门禁

只有同时满足以下条件才允许生成完整讲稿：

- 全部正式PPT页面的内容与视觉均已确认；
- 页面拆分、合并和顺序调整已经结束；
- 最终页码、`slide_id`、标题、批准PNG和页面总数已锁定；
- Proposal Owner 明确确认以当前PPT生成讲稿。

策略草稿、目录、章节论证链、PPT内容稿和视觉评审阶段，只记录演讲任务，不生成完整讲稿。

演讲稿以最终PPT为唯一内容输入，以飞书文稿为团队协作母版。每页同时使用最终页码和稳定 `slide_id` 作为标题锚点：

```text
[第12页｜P12] 页面标题
演讲任务：评审听完后应得出什么结论
建议时长：60-90 秒
讲稿：...
转场：如何进入 P13
可能追问：...
回答要点：...
```

HTML 不承载完整演讲稿，只保留 `speaker_doc_anchor`。飞书不可用时，先写入 `content/speaker-notes.md`，之后按最终页码和 `slide_id` 同步。

讲稿必须一次性按全案最终顺序生成，再连续朗读。讲稿负责解释当前批准画面的意义和推动下一页，不逐字复述标题、卡片和表格；如果读起来像报告摘要、广告旁白或由连接词拼接的长句，返回重写。

朗读通过后再做说服力检查：如果讲稿只给出正确、完整、客观的信息，却没有形成观点、情绪变化和客户决策推动，仍然返回重写。事实准确用于守住边界，不得把讲稿写成风险备忘录或中立研究报告。

### 页序一致性

- 讲稿条目数必须等于最终正式PPT页面数。
- 每条讲稿的最终页码、`slide_id` 和页面标题必须与批准页面一致。
- 章节交界页必须依据最终顺序重写转场，不复用早期章节稿中的旧转场。
- 页面换序、拆页、合页、标题或核心画面修改后，对应讲稿及前后转场立即过期。
- 更新后重新核对首页、各章节首尾页和感谢页，并连续朗读全案。

## 页级信息规则

- 一页一个核心结论，不用缩字承载两个完整任务。
- 方法论和完整样例通常拆页。
- 一个完整脚本、工作件、场景 Demo 或复杂时间系统优先独占一页。
- 标题表达判断，不写“市场分析”“执行规划”等空泛名词。
- 删除品牌名后可原样放入任意行业报告的页面不通过；必须补足品牌专属判断、选择理由或执行证明。
- 主标题不以中英文句号收尾，保持提案标题的判断感与视觉收束；正文、图注、来源和表格说明可正常使用标点。
- 数据必须给出时间、口径和内部证据编号；外部页脚只展示必要短来源。
- 对外不写 `待确认`、`内部使用`、`需法务确认`、Agent 名称或版本治理规则。

## 冻结

PPT内容页面确认后记录确认人、时间和确认记录 ID。全案对抗检测通过后，由 Owner 生成内容冻结 ID。`freeze_deck_spec.py` 为每页写入批准内容哈希；任何上屏文案、证据或视觉意图改变都会使该页过期。完整讲稿在最终PPT确认后生成；讲稿锚点改变需要重新执行页序映射QA。

内容确认与视觉成稿确认是两道不同门禁。视觉评论循环中，评论已处理不等于页面成稿确认；只有 Proposal Owner 明确确认对应 `slide_id` 后，该页 HTML 对应的 PNG 才能进入 `deck/assembly-ready/`。最终 PPT/PDF 在全部正式页面确认后一次性拼装。
