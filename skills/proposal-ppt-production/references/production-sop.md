# 高设计感提案 PPT 生产标准 v1.0

> 用途：作为 `proposal-ppt-production` Skill 的通用生产规范。  
> 核心目标：在完整叙事逻辑与商业信息密度不下降的前提下，稳定生成具有提案感、品牌感和视觉关注点的页面。

## 1. Skill 的任务边界

这个 Skill 负责把经过确认的提案原文转化为可审阅页面，并在最终批准后组装完整 PPT，包括：

- 梳理叙事顺序与页面角色。
- 固定整套设计语言和页面节奏。
- 判断每页采用 HTML 排版、Image2 视觉，还是两者混合。
- 生成并校对页面 PNG。
- 在所有必需页面明确批准后组装 PPTX，渲染整套预览并完成质量检查。
- 根据用户批注进行局部修订，不破坏已经确认的页面。

这个 Skill 不负责：

- 擅自改写尚未确认的核心策略结论。
- 编造数据、来源、产品利益或技术证据。
- 将所有页面统一做成 KV、海报或低信息量情绪图。
- 在没有确认的情况下覆盖已交付版本或合并到仓库。

## 2. 最高优先级原则

### 2.1 先叙事，后设计

整套提案必须形成累积推演，而不是页面集合。每页只承担一个明确的叙事任务，并回答上一页提出的问题或为下一页建立必要性。

建议使用以下结构：

`背景与机会 → 核心判断 → 证据 → 策略选择 → 内容与直播执行 → 经营闭环 → 行动与收束`

### 2.2 可视化原文，不是把原文全部视觉化

- 原文中的因果、阶段、对比、循环、路径和优先级应被可视化。
- 解释、限制条件、数据来源和精确数字必须保留为可读文字。
- 不应把每页都压缩成一句口号和一个大画面。
- 不应为了“设计感”降低信息完整性或改变原意。

### 2.3 第一眼抓结构，第二眼读完整信息

一页合格的内容页应同时具备：

1. 第一眼可识别的主结论或主结构。
2. 3—8 秒内可理解的阅读顺序。
3. 能够完整支持结论的解释、证据和来源。

### 2.4 Image2 与 HTML 各自承担擅长的部分

- Image2：空间构图、核心装置、材质、人物或产品场景、情绪与视觉焦点。
- HTML：精确标题、正文、数据、来源、注释、页码和品牌规范。
- 混合页：Image2 提供视觉底层，HTML 提供准确的信息层。

## 3. 标准输入与输出

### 3.1 必需输入

- 完整提案原文或经过确认的页面大纲。
- 品牌名称、项目名称、受众和提案目标。
- 品牌资产：Logo、产品图、包装图、指定字体与色彩。
- 数据来源与不可改写的产品证据。
- 已确认的参考页或视觉方向。

### 3.2 可选输入

- 现有 PPTX、PDF 或设计模板。
- 图片参考、竞品页面、情绪板。
- 每页批注和禁止项。

### 3.3 标准输出

- 评审阶段：可编辑 HTML、每页 1920×1080 PNG、新旧对照图、页面状态记录。
- 最终批准后：16:9 PPTX、PDF（如需要）及整套渲染总览。
- 整套缩略图总览。
- 关键版本的新旧对照图。
- 来源记录、页面清单和 QA 结果。
- 可复用的 HTML、CSS、生成提示词和组装脚本。

## 4. 页面角色体系

不同页面承担不同的信息密度，不允许用同一种 KV 逻辑覆盖全套。

| 页面角色 | 主要任务 | 推荐视觉强度 | 推荐信息密度 | 典型构图 |
|---|---|---:|---:|---|
| 首页 | 建立主题、品牌与提案气质 | 高 | 低 | 产品／符号主视觉＋极简标题 |
| 目录页 | 说明完整推演路径 | 中高 | 中 | 连续路径、递进空间或章节地图 |
| 章节页 | 切换叙事阶段 | 高 | 低 | 大标题＋章节符号＋留白 |
| 判断页 | 给出核心策略结论 | 中高 | 中 | 大判断＋一组关键证据 |
| 证据页 | 支撑判断 | 中 | 中高 | 数据、对比、阶段或因果结构 |
| 方法页 | 说明如何执行 | 中 | 高 | 流程、结构、脚本或模块关系 |
| 案例／场景页 | 让策略可感知 | 高 | 中 | 人物、产品、直播或生活场景 |
| 经营页 | 建立指标与迭代关系 | 中高 | 高 | 循环、漏斗、驾驶舱或闭环 |
| 结尾页 | 回收主张并推动下一步 | 高 | 低 | 核心主张、行动请求、感谢 |

### 页面节奏

- 高视觉页之后安排一页可深入阅读的内容页。
- 连续两页高密度之后，应出现一页低密度的章节页、判断页或场景页。
- 同一章节内避免连续使用完全相同的版式骨架。
- KV 风格页面在整套中只作为节奏峰值，不作为默认页面。

## 5. 设计语言规范

### 5.1 画布与安全区

- 画布：1920×1080，16:9。
- 左右主安全区：80—120 px。
- 上安全区：32—72 px；下安全区：24—56 px。
- 标题、来源和正文不得贴边。
- 重要文字不得依赖播放器裁切区或装置边缘。

### 5.2 项目视觉 Token

- 颜色、字体、材质、深浅页面节奏和品牌资产全部读取项目已确认的 `DESIGN.md`。
- 本规范不提供可直接套用的客户配色；缺少 `DESIGN.md` 时只能制作少量校准页，不能批量生产。
- 同一页面角色的视觉 Token 必须稳定，页面变化来自内容任务与最佳载体，而不是随机换风格。

### 5.4 字体层级

| 层级 | 建议字号 | 规则 |
|---|---:|---|
| 封面主标题 | 58—78 px | 1—2行，避免解释段落 |
| 内容页主标题 | 46—64 px | 优先结论型标题 |
| 章节页标题 | 64—88 px | 可配章节数字或符号 |
| 核心数字 | 72—140 px | 一页通常只有一个主要数字锚点 |
| 模块标题 | 24—36 px | 视觉上必须明显高于正文 |
| 正文 | 22—26 px | 不以缩小字号解决信息过多；20px 仅用于次级说明 |
| 注释／来源 | 12—15 px | 保证投屏可辨识，避免低对比 |

- 中文主标题可使用思源宋体粗体，形成品牌编辑感。
- 正文、数据和英文使用思源黑体。
- 一页最多使用两种字体家族、四种字重／字号层级。
- 标题若需要缩到 40 px 以下，优先改写或重构页面。
- 同一页面角色的核心字体跨页必须使用同一档位：内容页标题默认 `52—56px`，模块标题默认 `30—40px`，正文默认 `22—26px`。
- 相邻同类页面的同级字体变化原则上不得超过 `4px` 或 `8%`；需要刻意形成高潮时，必须由页面角色变化解释，不能由内容多少随机决定。
- 不允许一页正文为 `24px`、下一页因布局不足骤降到 `18px`。优先扩大信息区、压缩无效空白或拆页。

### 5.5 留白与有效占版率

留白必须承担明确作用：聚焦主标题、分隔信息层级、引导视线或为主视觉提供呼吸。无法说明作用的留白属于**无效空白**，必须重新分配。

- 信息主导页的文字、图表与必要视觉应覆盖约 `68%—82%` 的有效内容区。
- 混合主导页的文字与主视觉合计应覆盖约 `62%—78%` 的有效内容区。
- 设计主导页允许更低密度，但连续无意义空白不得超过画布约 `10%`；章节页也不能在标题区与页尾之间留下无法解释的“死区”。
- 单一连续空白区域若超过画布约 `8%`，必须回答它是否在聚焦、分隔或引导；若三者皆否，判定为版面失衡。
- 当信息被压缩在局部区域、同时另一侧存在大块空白时，优先扩大文字容器与字号，不通过增加装饰填空。
- 缩略图中若出现明显的空白矩形、空白走廊或左右重量悬殊，即使全尺寸文字未溢出，也不得通过 QA。

### 5.6 构图规则

- 使用非等分构图，避免机械的左右 50/50、三等分和六宫格。
- 信息模块可以错位、递进或沿视觉路径排布，但阅读顺序必须明确。
- 每页至少有一个清晰关注点：大数字、产品、人物、核心装置或强判断。
- 卡片只在信息确实需要独立分组时使用；不得把普通段落全部卡片化。
- 装饰元素不得比策略结论更醒目。

### 5.7 图片与装置

- 产品图必须保持真实包装、Logo 和关键卖点，不得生成错误包装。
- 生活场景、材质装置和抽象视觉可由 Image2 生成。
- 生成图片应为 16:9，并为准确文字预留可用空间。
- 视觉装置应表达内容关系，例如：递进、循环、包埋、连接、选择或放大。
- 不用无意义的科技粒子、随机分子式或医疗器械感冒充“专业”。

## 6. 信息与文案规范

### 6.1 页面信息结构

每页至少明确以下四项：

1. 页面叙事任务。
2. 主结论。
3. 支撑主结论的必要信息。
4. 与前后页的逻辑关系。

### 6.2 标题规则

- 标题优先表达判断，不只命名主题。
- 标题应能由提案人自然说出口。
- 避免连续使用“从A到B”“不仅……更……”等模板化结构。
- 不把执行说明、生产备注或提示词写进观众可见页面。

### 6.3 信息密度

- 一页只设一个主结论，但可以有多项必要证据。
- 能合并为一个逻辑句的内容，不拆成多个小卡片。
- 先删重复信息，再考虑减字号。
- 解释文字一般控制在 3—6 个信息单元；方法页可更高，但必须分层。

### 6.4 数据与来源

- 数字、单位、年份、百分比和专利名称由 HTML 精确输出。
- Image2 不负责生成必须完全准确的数据和小字。
- 数据不得脱离来源改变含义。
- 每个外部事实页保留来源，来源与正文保持足够对比度。

## 7. 生成前的内容模式判定

页面进入 Image2 之前，必须先判定**表达对象与最佳载体**，再判定内容模式。表达对象决定“用什么呈现”，内容模式决定“承载多少、视觉多强、Image2 与 HTML 如何分工”；不得因为信息量高就默认使用表格，也不得先生成视觉再被动补回信息。

### 7.0 表达对象与最佳载体

第一层判断不是“信息多不多”，而是“受众需要看见什么，才能最快理解这一页”。

| 表达对象 | 典型内容 | 默认最佳载体 | 精确层职责 | 禁止退化 |
|---|---|---|---|---|
| 数据与比较 | 指标、占比、趋势、差异、参数、行业报告 | 图表、表格、量化矩阵 | 数字、单位、图例、来源全部由 HTML／原生图表输出 | 用情绪图片替代数据关系 |
| 场景与动作 | 直播间、短视频镜头、早餐、试饮、送达、人物状态 | 场景图片、故事板、连续关键帧 | 时间、台词、证据与动作标签由 HTML 输出 | 因信息量高而做成纯表格 |
| 关系与机制 | 路径、循环、因果、漏斗、协同、包埋机制 | 关系图、路径装置、流程图 | 节点名称、解释、数据与来源由 HTML 输出 | 用无关大图遮蔽逻辑关系 |
| 工作件与执行物 | 脚本、作战单、内容卡、选品清单、复盘表 | 真实工作件模拟、界面化文档或标注样张 | 所有可执行字段与文字由 HTML 输出 | 做成抽象 KV，失去可执行性 |
| 主张与转场 | 首页、章节命题、核心创意、结尾收束 | KV、主视觉、单一强判断 | 标题、Logo、证据与品牌信息由 HTML 输出 | 塞入不必要的表格与细节 |

判断原则：

- **信息主导不等于表格主导。** 场景信息即使包含六个以上信息单元，也应先以图片或故事板建立理解，再用文字标注补全。
- **场景页先让受众看见“发生了什么”。** 只有无法从画面准确传递的时间、台词、数据、证据和行动任务才进入 HTML。
- **数据页先让受众看见“关系是什么”。** 图片只能提供语境，不得成为数据主体。
- 混合页面只允许一个主载体；其他载体退为解释层，避免图片、表格和装置同时争夺第一视觉焦点。
- 如果把页面主载体删除后，受众无法完成页面的核心理解任务，说明主载体选择正确；如果删除后理解几乎不变，说明载体只是装饰。

### 7.0.1 最佳载体快速判断

生成任务单前依次回答：

1. 受众要比较数字，还是看见一个真实发生的场景？
2. 页面结论依赖“数值关系”“动作顺序”“空间关系”还是“情绪与状态”？
3. 如果只能保留一种载体，图表、场景图片、关系图、工作件或一句主张，哪一种损失最小？

选定主载体后，才进入信息主导／设计主导／混合主导判定。

### 7.1 三种内容模式

| 模式 | 典型页面 | 第一目标 | Image2 职责 | HTML 职责 | 主要风险 |
|---|---|---|---|---|---|
| 信息主导 | 数据、图表、行业报告、证据、对比、产品参数 | 准确理解与建立可信度 | 表达数据关系、场景与视觉层级；不承担精确图表绘制 | 精确数据、图表、标签、解释和来源 | 被错误压缩成低信息量 KV |
| 设计主导 | 首页、章节页、情绪峰值、转场、结尾 | 建立注意力、气质和节奏 | 主构图、材质、空间、人物、产品与情绪 | 标题、品牌、页码和少量精确文字 | 视觉漂亮但与内容无关 |
| 混合主导 | 路径、循环、机制、漏斗、三阶段演进、方法框架 | 同时看懂结构与感知价值 | 生成完整关系装置和视觉路径 | 精确节点、解释、数据、来源 | 结构被装饰淹没，或重新变成卡片页 |

### 7.2 判定规则

先回答以下问题：

1. 页面是否包含必须逐项读取的数字、图表、报告结论或四项以上证据？
2. 受众是否需要比较、验证、判断趋势或理解差异？
3. 如果删除正文，只保留一句标题和一个画面，页面结论是否会失真？
4. 页面主要任务是否只是建立章节气质、情绪峰值或转场悬念？

判定方法：

- 问题1—3中有两项为“是”：判定为**信息主导**。
- 问题4为“是”，且事实单元不超过两项：判定为**设计主导**。
- 存在明确关系模型，同时需要3—6项解释或数据：判定为**混合主导**。
- 无法判断时，默认选择信息容量更高的模式，不默认做 KV。

### 7.3 生成任务单

每页在生成前必须先写：

```text
页面编号：
页面角色：
表达对象：数据 / 场景 / 关系 / 工作件 / 主张
最佳主载体：图表表格 / 场景图片故事板 / 关系图 / 工作件 / KV
内容模式：信息主导 / 设计主导 / 混合主导
叙事任务：
主结论：
必须保留的信息单元：
必须准确的数字与来源：
需要被可视化的关系：
Image2职责：
HTML职责：
禁止退化成：KV / 卡片网格 / 纯文字线稿 / 无关装饰
```

只有内容模式和职责分工完成后，才允许编写 Image2 提示词。

## 8. 页面视觉路线选择

内容模式决定“页面首先服务什么”，视觉路线决定“页面如何实现”。默认映射如下：

| 内容模式 | 默认路线 | 允许例外 |
|---|---|---|
| 信息主导 | Route A 或 Route C | 只有信息单元极少时才可使用 Route B |
| 设计主导 | Route B | 需要少量解释时可使用 Route C |
| 混合主导 | Route C | 关系非常简单时可退回 Route A |

### Route A：HTML 主导

适用于：

- 文字、数据和逻辑关系需要高度准确。
- 页面以对比、列表、证据或流程说明为主。
- 不需要复杂材质、人物或空间装置。

标准：HTML 负责全部文字和结构，图片仅作为辅助视觉。

#### Route A-T：HTML 信息层＋Image2 透明辅助元素

这是路径、步骤、矩阵、对比和方法页的默认增强路线，用于解决纯文字页面过于单一的问题，但不改变其“信息主导”属性。

- HTML 继续承担 `100%` 的标题、正文、数字、表格、节点、标签和来源。
- Image2 只生成真透明背景的 `PNG` 元素，不生成整页背景。
- 元素必须表达页面关系，例如双路径、递进、连接、包埋、汇合或分流；不得只是填空装饰。
- 元素实际着色面积一般控制在画布约 `8%—18%`，每页最多 `1—2` 个连续元素簇。
- 透明元素不得覆盖关键文字；置于信息层后方时，合成透明度控制在 `12%—28%`。
- 页面注意力顺序必须保持为：主标题 → 关键结论／结构 → 证据 → 辅助视觉。

适用判断：如果页面删除辅助视觉后仍能完整传递信息，但缩略图呈现明显“纯文字线稿感”，则采用 Route A-T。

### Route B：Image2 主导

适用于：

- 首页、章节页、结尾页或强场景页。
- 信息量较低，主要任务是建立气质和注意力。
- 文字可以控制在标题、数字和短语范围内。

标准：Image2 负责主构图，HTML 只覆盖标题、Logo、页码和必要准确文字。

### Route C：Image2＋HTML 混合

适用于：

- 原文存在明确的递进、路径、循环、对比或中心装置。
- 纯 HTML 会显得像线稿，纯 Image2 又无法保证文字准确。
- 页面既需要视觉冲击，也必须保留较高信息密度。

标准：

- Image2 生成完整视觉底层和主要关系。
- HTML 补充解释、数据、来源与品牌 Chrome。
- HTML 不重新覆盖成大面积白板或等分卡片。

## 9. Image2 生成 SOP

### 9.1 信息主导提示词逻辑

信息主导页先输入完整的数据结构和阅读任务，再描述设计语言。提示词必须明确写出“这不是 KV”。

```text
这是信息主导的商业提案页面，不是广告KV。

受众需要完成的阅读任务：{比较/理解趋势/判断差异/验证结论}
主结论：{一句话}
完整信息单元：{逐项列出，不得省略}
数据关系：{时间趋势/对比/构成/阶段/因果}
必须准确的数据：{数字、单位、年份}
由HTML绘制的内容：{精确图表、表格、数字、来源}

Image2只负责：
- 建立与数据关系一致的空间结构、场景或视觉隐喻；
- 为图表、数字和解释预留明确区域；
- 强化阅读顺序和一个主要关注点。

禁止：把页面压缩成一句口号和一个大装置；删除信息单元；
虚构数据；让装饰压过图表；平均卡片网格；随机英文。
```

信息主导页验收：

- 缩略图中能看到结构，放大后能完整读取证据。
- Image2 不生成必须精确的统计图形；图表由 HTML 或原生图表工具绘制。
- 视觉不能占用数据阅读所需的主要面积。
- 页面删除任一必要证据后均应重新评估，而不是以“更简洁”为理由接受。

#### 9.1.1 信息页透明辅助元素提示词

```text
为16:9高端商业提案的信息页生成一个独立的透明PNG辅助视觉元素。
这不是整页KV，不生成背景，不生成版式，不生成任何文字。

页面主结论：{一句话}
页面结构：{五步路径/双轨比较/矩阵/递进关系}
需要被轻度强化的关系：{连接/分流/汇合/递进/留存}
元素形式：{蓝金双轨/包埋环线/低透明乳流/钙核心局部/节点连接带}
预期位置：{右下边缘/表格后方/路径转折处/段落间隙}

输出要求：
- 真透明背景RGBA PNG，四角完全透明；
- 单一连续元素簇，构图轻盈，实际着色面积低；
- 无中文、英文、数字、Logo、包装、认证、图标和随机符号；
- 不出现白底、棋盘格、完整海报背景或实心大色块；
- 材质、颜色与项目 `DESIGN.md` 一致；
- 视觉权重低于标题、节点、表格和关键数据。
```

技术验收：文件须识别为带 Alpha 通道的 PNG；四角像素透明。若输出为白底、棋盘格或整页背景，必须重新生成或完成可靠抠图后再进入排版。

### 9.2 设计主导提示词逻辑

```text
这是设计主导的商业提案页面，主要任务是建立注意力、品牌气质和章节节奏。

页面角色：{首页/章节/转场/结尾}
主结论或情绪：{一句话}
视觉隐喻：{门户/轨道/聚合/放大/开启}
第一视觉焦点：{产品/人物/装置/一句话}
HTML后期文字：{标题、品牌、页码}

Image2负责完整构图、空间、材质、光线和情绪峰值。
允许低信息密度，但视觉必须直接服务页面主结论。
禁止：无关科技装饰、随机英文、错误包装、泛化企业宣传画面。
```

设计主导页验收：

- 第一眼可明确感到章节任务或情绪变化。
- 画面与主结论存在可解释关系。
- 文字保持少量、大字号，不补成高密度卡片页。

### 9.3 混合主导提示词逻辑

```text
这是结构与视觉并重的商业提案页面。

主结论：{一句话}
完整原文：{全文}
核心关系：{路径/循环/三阶段/漏斗/机制}
必须出现的节点：{3—6个}
必须准确的数据：{数字、单位、来源}
Image2负责：完整关系装置、空间路径、材质和主标签。
HTML负责：节点解释、精确数字、来源和品牌规范。

必须让受众第一眼看懂关系，第二眼读取完整解释。
禁止：把关系拆成等分卡片；用一个大画面替代全部节点；
生成错误小字；为了视觉效果改变原文逻辑。
```

混合主导页验收：

- 主结构不依赖正文也能识别。
- 所有必要节点和解释仍然存在。
- Image2 与 HTML 沿同一阅读路径工作，不形成两个互相竞争的版面。

### 9.4 生成前先写页面语义包

每页输入应包含：

- 页面主结论。
- 完整原文信息。
- 内容关系：递进、循环、对比、因果或并列。
- 必须出现的主关键词。
- 不应进入图片的小字、数据和来源。
- 品牌色、材质、光线、视觉重心和留白方向。
- 禁止项：错误包装、随机英文、乱码、医疗恐惧感、平均切块。

### 9.5 通用视觉提示词骨架

```text
为16:9高端商业提案PPT生成一张完整视觉底层。

页面主结论：{一句话}
原文信息：{完整原文}
信息关系：{递进/循环/对比/因果/路径}
第一视觉焦点：{数字/产品/人物/装置}
必须可见的短文字：{不超过6组}
由HTML后期覆盖的精确内容：{数据、解释、来源}

设计语言：品牌编辑式、乳白主场、深海军蓝结构、香槟金强调，
使用非等分构图、真实空间进深、精致材质和清晰阅读路径。
为后期文字保留干净区域。

禁止：整页深蓝压迫、平均分割、卡片网格、随机英文、乱码、
错误产品包装、无关医疗器械、无法解释内容关系的装饰。
```

### 9.6 生成后检查

- 主结构是否与原文关系一致。
- 是否出现错误中文、数字、英文或品牌信息。
- 是否存在可以被 HTML 局部遮盖的小错字。
- 是否为正文与来源保留可读区域。
- 是否过度 KV 化，导致信息容量不足。

不能通过局部遮盖修复的页面必须重新生成，不得勉强使用。

## 10. HTML 精确层 SOP

- 画布固定为 1920×1080。
- 使用本地字体，等待字体和图片加载完成后再截图。
- 主标题优先使用 HTML；只有 Image2 已准确生成且版式不可拆时才保留栅格标题。
- 精确数字、解释段落、来源和页码必须使用 HTML。
- 注释层应沿 Image2 的视觉路径排布，不创建新的平均网格。
- 注释背景使用乳白半透明纸张、深蓝信息带或局部遮罩；只覆盖必要区域。
- 每次渲染自动检查元素是否超出画布、文字是否溢出。

## 11. 完整生产 SOP

### Gate 0：确认任务

- 明确受众、提案目标、页数范围、输出格式和是否允许外部搜索。
- 明确版本保存位置和是否允许覆盖、合并或提交。

### Gate 1：内容盘点

- 读取全部原文和来源。
- 建立“主张—证据—意义—下一步”表。
- 标记不可改写的数字、品牌名、专利名和来源。

### Gate 2：叙事地图

- 为整套写一句传播任务：受众最终应理解、相信或批准什么。
- 建立章节顺序和页面清单。
- 为每页写：页面角色、叙事任务、主标题、必需信息、与前后页关系。

### Gate 2.5：内容模式分流

- 将每页判定为信息主导、设计主导或混合主导。
- 记录 Image2 与 HTML 的职责分工。
- 信息主导页不得使用设计主导提示词。
- 无法判定时，以保留更多必要信息为原则。

### Gate 3：设计系统确认

- 先生产：首页、目录页、至少两种章节页、两种内容页、结尾页。
- 用总览图确认色彩、字体、留白、信息密度与页面节奏。
- 固定设计 Token，不固定每一页的版式。

### Gate 4：页面路线分配

- 对每页选择 Route A、B 或 C。
- 高密度页面默认从 A 或 C 开始。
- 首页、章节页和结尾页优先考虑 B。
- 任何页面不得因为使用 Image2 而删除必要原文。

### Gate 5：小批量校准

- 每次先生产 3—5 页代表性页面。
- 提供单页大图和整组总览。
- 用户确认后再连续生产，避免整套同方向返工。

### Gate 6：连续生产

- 按章节批量生成视觉与 HTML。
- 每完成一批，检查叙事衔接、页面节奏和视觉重复。
- 已确认页面不主动重做，只处理明确批注。

### Gate 7：单页 QA

- 原文完整且无错字。
- 标题、关键数字和主结构足够醒目。
- 字号、对比度、留白与图片焦点合理。
- 计算并目测有效占版率；不存在超过画布约 `8%` 且无明确功能的连续空白区域。
- 同类页面的标题、模块标题与正文字号落在锁定档位内，跨页变化不超过约 `4px` 或 `8%`。
- 信息区没有被压在局部小面积内；如存在大块空白，已优先扩大文字容器、字号与行距。
- 无错误品牌资产、错误数据或生成文字残影。
- 无越界、遮挡、意外重叠和异常换行。

### Gate 8：整套 QA

- 页数、页面顺序和章节逻辑正确。
- 高低密度页面节奏自然。
- 蓝白比例与品牌色一致。
- 同一视觉资产不被无意义重复使用。
- 首页与结尾形成回应，结尾明确下一步而非突然结束。

### Gate 9：组装与交付

- 前置条件：所有必需页面均由负责人明确标记为 approved / assembly-ready。
- 将最终 PNG 或可编辑元素嵌入 PPTX。
- 渲染 PPTX 全部页面并生成总览图。
- 运行溢出检测，确认页数、尺寸和文件可打开。
- 输出新版本，不覆盖旧版本，除非用户明确要求。

## 12. 反馈 Loop

```text
原文/批注
   ↓
定位问题类型
   ↓
判断修复层级：文字层 / HTML结构 / Image2局部 / Image2重生 / 叙事重构
   ↓
生成单页修订稿
   ↓
新旧对照
   ↓
用户确认
   ↓
标记当前页完成并进入 assembly-ready 库
   ↓
记录新规则，更新下一批生产标准
```

评审循环中不重复拼装 PPTX。每次批注只回写受影响的 HTML／视觉层，重新渲染对应 PNG 并复核；整套 PPTX/PDF 只在全部页面完成确认后一次性组装。

### 12.1 问题分类与修复动作

| 用户反馈 | 优先修复方式 |
|---|---|
| 错字、数据、来源错误 | HTML 精确层局部修订 |
| 字体偏小、阅读顺序弱 | 调整字号、层级和占版率 |
| 留白过空、没有关注点 | 先扩大信息区与核心字号；确有叙事需要时再增加主数字、人物或 Image2 装置 |
| 信息挤在局部、另一侧出现大块空白 | 重新分配容器宽高与页面重心，禁止同时缩字和保留死区 |
| 同级字体跨页忽大忽小 | 回到统一字号档位，只通过行数、宽度与内容拆分解决 |
| 页面像线稿或简版草稿 | Route A 升级为 Route C |
| 路径／矩阵页信息完整但纯文字过于单一 | 保持 Route A 信息结构，增加 Route A-T 透明 PNG 辅助视觉；不得改成 KV |
| 场景页信息完整但被做成表格 | 保留信息单元，主载体改为场景图片或连续故事板；表格退为局部标注 |
| 页面过度 KV、信息不足 | 增加解释层，或改为 HTML 主导内容页 |
| 深蓝铺满过于压迫 | 增加乳白主场和透明材质，降低深蓝面积 |
| 版面切割过于平均 | 改用错位、递进、路径或非对称构图 |
| Image2 有局部错字 | HTML 遮盖；无法遮盖则局部／整页重生 |
| 前后页逻辑跳跃 | 先修叙事地图，再修单页设计 |

### 12.2 修订范围控制

- 单字或数据错误只修改文字层。
- 层级问题只修改当前页结构，不重生无关视觉。
- 视觉核心错误才重新生成 Image2。
- 叙事任务改变时，必须重新检查前后页。
- 每次替换保留上一版和新旧对照，确认后再进入主版本。

## 15. 跨项目验证规则

以下规则来自多轮真实提案页面对照，可跨项目复用，但不得替代项目 `DESIGN.md`：

- 明暗页面需要形成节奏，连续同色满铺容易造成压迫或单调。
- 非等分、具有空间进深的构图通常比机械分栏更适合提案表达。
- Image2 能显著提升目录、行业演进和经营闭环等结构页的设计表现力。
- Image2 必须与 HTML 精确文字层结合，才能同时保证视觉冲击和信息完整。
- 内容页不应全部 KV 化；应根据页面任务在视觉峰值与高密度阅读之间切换。
- 用户确认应基于 HTML、直接 PNG、新旧对照和明确的页面状态；浏览器批注只是反馈入口，不等于批准。
