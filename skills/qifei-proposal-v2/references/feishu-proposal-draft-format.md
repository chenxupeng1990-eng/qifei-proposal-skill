# 飞书PPT提案成稿格式

## 1. 文档定位

飞书文档是PPT内容、策略逻辑、页面讲解方向和视觉生产建议的团队协作母版。它不是最终演讲稿，也不是把PPT截图堆进文档。

每个页面单元必须让策划、客户负责人、设计和后续生成Agent同时看懂：

- 这页最终要表达什么；
- 它如何承接前页并推进总策略；
- PPT画面上需要出现哪些内容；
- 现场讲解应强调什么；
- 视觉应该用什么主载体实现。

完整演讲稿等待全部PPT页面、拆页和最终顺序确认后，另行按最终页码生成。

## 1.1 权威来源与回读凭证

飞书提案文档是内容确认阶段的唯一权威母版。本地 Markdown 只能作为飞书整份回读后的可审计快照，或在飞书暂时不可用时承担待同步草稿。

每轮写入或评论修改后必须：

1. 重新抓取整份飞书文档，不以写入接口返回成功代替回读；
2. 保存快照到 `content/feishu/proposal-draft.md`；
3. 计算快照 SHA256；
4. 在 `project-state.json.proposal_draft` 记录：
   - `authority: "feishu"`；
   - `status: "verified"`；
   - `format_version: "feishu-proposal-draft-v1"`；
   - `feishu_doc_url`；
   - `document_id`；
   - 正整数 `revision_id`；
   - `last_verified_at`；
   - `verified_snapshot_path`；
   - `verified_snapshot_sha256`；
   - 与已确认页序完全一致的 `verified_slide_ids`。

缺少任一字段、快照哈希不匹配、飞书页序与章节状态不一致，或回读快照缺少本格式规定的章节／页面字段时，均不得登记为内容已确认。

飞书不可用时将状态记为 `local_fallback_pending_sync` 并填写 `fallback_reason`。该状态不能进入全稿审查、内容冻结或视觉生产。

### 1.2 临时插页与拆页

视觉或评审阶段临时提出的新页、拆页、合页，先登记在 `content/feishu/page-change-proposals.md`，记录来源页、拟议位置、修改理由和受影响的前后过桥。候选页不得进入 `chapters[].slides`、`deck-spec.json`、拼装准备库、最终页序或讲稿。

Owner 接受变更后，先回写飞书并完成整份回读，再更新 `verified_slide_ids`、章节页序和本地快照；只有这些对象完全一致，候选页才转为正式页。Owner 放弃的候选页直接删除，不保留虚假的正式状态。

## 2. 章节格式

每章使用以下结构：

```text
# 章节名称｜本章承担的策略动作或结论

本章回答：
用一句话说明总策略推进到这里必须解决的问题。

逻辑路径：
上一章已经证明什么 → 本章需要进一步证明什么 → 本章结束后形成什么结论 → 为什么必须进入下一章。

情绪方向：
本章开始时观众处于什么状态，在哪个节点产生张力，最终形成什么信心或期待。
```

章节名称不能只是“行业分析、内容规划、运营保障”等业务栏目。

## 3. 单页标准格式

### `[slide_id]｜结论式标题`

#### 核心内容

用1—2句话写清本页必须成立的核心判断。它是PPT屏幕与讲解共同服务的中心，不写资料摘要。

#### 逻辑展开

根据页面任务选择最合适的结构，示例：

- 事实 → 行业意义 → 品牌判断；
- 消费者问题 → 产品证据 → 选择理由；
- 策略选择 → 执行动作 → 验证方式；
- 场景 → 痛点 → 功能 → 利益 → 商品行动；
- 输入 → 机制 → 输出 → 下一步。

可以使用表格、分栏、流程、数据、脚本、故事板或工作件。不得为了格式统一，强行把所有页面写成三列卡片。

#### PPT上屏内容

列出最终画面需要精确出现的：

- 标题与副标题；
- 核心数字；
- 正文短句；
- 图注、标签和来源；
- 脚本、工作件或Demo中的必要文字。

这一部分决定HTML精确文字层，不等于完整讲稿。

#### 讲解方向

用30—80字说明讲者如何解释本页：

- 从上一页哪个结论进入；
- 本页重点解释“为什么”还是“怎么做”；
- 哪个判断需要停顿或强调；
- 最后用什么问题或结论进入下一页。

只写讲解方向，不提前扩写逐字讲稿。

#### 策略与过桥

- `strategy_link`：本页服务总策略的哪一步；
- `prior_page`：继承前页哪个已成立结论；
- `current_advance`：本页新增什么判断、选择、动作或证明；
- `next_page_need`：为什么下一页必须出现。

这些字段供内部协作使用，不进入最终PPT画面。

#### 视觉生成建议

至少包含：

- **视觉锤**：第一眼必须看到的唯一对象或关系；
- **主载体**：数据图、关系图、真实场景、脚本故事板、工作件、时间线、驾驶舱或完整主视觉；
- **构图方向**：主要对象位置、阅读路径和视觉停点；
- **Image2任务**：需要生成的背景、场景、概念图或透明PNG模块；
- **HTML任务**：必须精确可编辑的标题、数据、图表、关系和来源；
- **素材需求**：官方产品、Logo、人物、案例截图、后台数据或其他真实资产；
- **避免事项**：本页最容易出现的误读、拼贴感或信息拥挤问题。

视觉建议描述“如何让观点被看见”，不只描述颜色、装饰和版式。

#### 证据与来源

记录内部证据编号、来源名称、时间和必要口径。最终PPT只显示必要短来源。

## 4. 飞书排版建议

为了便于浏览和评论：

- 章节使用一级标题，页面使用二级标题；
- 页面核心判断使用加粗首段；
- 结构化内容使用表格、分栏或流程；
- 页面最终结论可用引用块收束；
- “讲解方向、视觉生成建议、来源”使用弱化文本或固定标签；
- 每页保持完整内容单元，避免跨页面锚点混写；
- `slide_id` 保留在飞书标题中，最终PPT不显示内部编号。

## 5. 放行标准

页面满足以下条件才可进入PPT视觉生产：

- 核心内容是判断，不是信息摘要；
- 逻辑展开能够证明核心判断；
- 上屏内容已明确且可拆分为精确字段；
- 讲解方向能说明如何解释，而不是复述屏幕；
- 本页与前后页存在真实策略关系；
- 视觉建议已经指定主载体和Image2/HTML分工；
- 证据与来源可以回查；
- 未提前生成完整演讲稿。

除页面质量外，项目还必须存在有效的飞书回读凭证。Owner 的“确认”只批准当时看到的内容，不替代 revision、整份回读、格式完整性、页序一致性和快照哈希校验。
