# 页面路由、生产与评审Loop

## 每页生产路由

调用Image2或编写HTML前，为每张正式页记录 `presentation_route`：

- 服务对象、使用情境和演讲任务；
- 核心思想、内容关系与需要被看见的表达对象；
- 最佳载体、唯一主导类型和视觉锤；
- 首眼对象、阅读路径和最终焦点；
- Image2决策、语义角色、`visual_family_id` 和资产；
- 必须由HTML保护的文字、数据和关系；
- 视觉重量计划与孤儿元素检查。

不得先套HTML版式，再把内容和图片硬塞进去。

## Image2与HTML

- 每张正式页以一张已登记的 Image2 整页设计底图为主体（`visual_mode: background`，`semantic_role` 为 `scene` 或 `hero`），尺寸不小于 1920×1080、比例 16:9，`validate_design_loop.py` 会检查；
- 先生图，再由 HTML 编排文字和数据，给设计最大空间。生图前只按本页文字量和密度定文字区的位置与大致面积并写进提示词，不做具体排版；数据页、目录页、结尾页同样有底图，只是底图更克制；
- 生图后 HTML 按实际画面编排，文字放在真正干净的明暗过渡区；放不下时先用信息带、遮罩、卡片等 DESIGN.md 定义的组件承接，仍不行再重生底图或拆页；
- 数据和比例由 HTML 在干净区域承担，图像不画定量条形或柱子；
- 底图要能独立成立：去掉文字层后，它本身是一张有构图、光线和留白的完整画面，而不是纯色背景上放几张图；
- 画面铺满整页：文字区是同一场景里的留白（墙面、天空、虚化的前后景、暗部），不是空白画布。空白底上横放一条图片带、或者只在中间放几个物体、其余全是平涂底色，都不算整页底图；
- 参考图数量受工具上限约束：通常是母版 1 张加本页实际出现的产品图，总数不超过生图工具允许的张数；
- 同一张母版只沿用版式、文字区、光线和材质；每页的机位、空间和画面主体必须不同。母版画面里的产品不随参考图带入，提示词写明本页只出现哪些产品；
- 身体护理类画面用手、手臂、肩颈局部和穿着衣物的人物，避免大面积裸露肌肤，否则容易被图像服务的安全系统拦截；
- 底图的主体就是本页的最佳载体和视觉锤：数据页让比较本身成为画面，流程或循环页让关系成为空间装置，内容样张页让故事板或成品出现，产品页只出现本页讨论的产品。去掉文字后，要能看出这一页在讲什么；
- 通用氛围图不算最佳载体：同一面墙、同一机位换几句文字反复用，判为主题配图失败，退回重选载体。不同页面不得共用同一张底图；
- **按母版生图**：设计校准通过后，每类页面已确认的校准页就是这一类的母版。生成正式页底图时，把同类母版页的 PNG 和官方产品图一起作为参考图交给 Image2，要求沿用母版的版式结构、文字区位置、光线和材质，只按本页最佳载体改变画面主体。在 `image2_decision.master_reference` 登记所用母版页；
- 放在方框、卡片、缩略图里的配图，以及无关背景、装饰纹理、为过门禁加的角标，都不计入视觉底线；
- 机制图、无文字语义图标和透明PNG可以作为底图之上的补充，不能替代底图；
- 个别页面确需其他路线时，在页面上登记 `route_exception`（`record_id`、`reason`），`record_id` 必须是 Owner 对该页的批准记录；`DESIGN.md` 或校准结论不能代替；
- 产品是场景主对象时，优先让真实产品参考与场景同光源、同透视、同接触阴影；
- Image2不生成精确正文、数据表、图表标签和需要严密核对的多步关系；
- HTML负责准确文字、数据、表格、时间线、流程和关系标注，但不能独立承担整页审美。

## 整页生图页面（render_route: image_full）

视觉表现型任务（`task_nature: visual_showcase`）的默认路线；说服型任务里只有带 Owner 批准的 `route_exception` 才能用。

1. **出图**：把本页冻结的上屏文字（逐字）和设计要求（母版、文字位置、字体气质、留白）一起写进提示词，参考图仍是同类母版和官方产品图。deck-spec 里登记 `render_route: "image_full"`、`visual_mode: "background"`。
2. **核对文字**：出图后由能看图的 Agent（或 OCR）逐行读出图上的文字，写进 `deck/review/image-text/<页面ID>.json`：

   ```json
   {
     "slide_id": "P03",
     "png_sha256": "<这张最终图的 SHA256>",
     "recognized_lines": ["图上读到的第一行", "第二行"],
     "fixes": [{"region": {"x": 820, "y": 140, "w": 420, "h": 90}, "before": "错字", "after": "正字"}],
     "checked_by": "Agent 名称",
     "checked_at": "2026-10-30T10:00:00+08:00"
   }
   ```

   `recognized_lines` 必须是真实读出的文字，不是把母稿抄一遍。
3. **修字**：有错字、漏字、多字，框出出错区域，用生图工具的局部编辑（蒙版重绘）只重画这一块；修完重新读一遍，把修过的区域写进 `fixes`，`png_sha256` 换成修好后的图。生图工具不支持局部编辑时，按 doctor 的 `image_edit` 缺口先问用户；用户接受降级才整页重生成。
4. **进入成品库**：`manage_assembly_ready.py approve --direct-png <图> --slide-id <页面ID>` 会用这份记录逐行比对母稿上屏文字，图换过或文字不一致都会被拦下。`final_check.py` 同样按这份记录核对；导出的 PPTX 里这些页是整页图片，跳过文字比对。

## 固定画布

- 导出画布固定为1920×1080、16:9；
- 浏览器响应式预览与真实导出画布分别验证；
- 检查文字裁切、换行、越界、遮挡、孤儿元素、字体替代和图片失效；
- 单页通过后检查整章montage中的视觉节奏和跨页一致性。

## 评审Loop

> 模板 → Image2核心表达 → HTML精确内容 → 固定画布QA → 整章montage → 浏览器评论 → 修改权威源 → 重建

评论循环使用HTML＋逐页PNG，或直出PNG＋Codex浏览器原生评论。修改必须回到冻结内容、页面路由、Image2源资产或HTML源文件，不直接修补最终PNG。

## 独立视觉审查（对抗检测）

全部正式页生产完、交 Owner 逐页确认之前，做一次独立视觉审查，要求和全稿审查相同：

1. 先运行 `node scripts/check_page_layout.mjs <项目目录> <页面HTML...>`，生成 `reviews/visual/LAYOUT-CHECK.json`：孤字尾行、文字越界或被裁切、文字压在纹理上、左缘差几像素。脚本报出的问题先改掉。
2. 新开一个独立 Agent（新上下文或独立 API 调用）。只给它：提案意图一句话、`DESIGN.md` 第 14 节视觉 QA 清单、每页 PNG。不给生产过程、其他审查和批准记录。它的任务是找问题，不是确认。
3. 报告写到 `reviews/visual/`，每页逐项给结论：`single_focus`、`orphans`、`alignment`、`text_on_texture`、`overflow`、`hierarchy`，并记录该页 PNG 的 SHA256、`review_agent_id`、`independent_agent: true`、`layout_check_report`。
4. 在 `project-state.json.visual_review` 登记 `report_path`、`review_agent_id`、`independent_agent`。
5. 页面在审查后有任何改动（PNG 哈希变化），这一页必须重新审查。`validate_project.py` 从讲稿阶段起检查：每页都审过、哈希一致、版面测量为零问题。

独立视觉审查通过不等于页面确认；页面仍由 Owner 逐页确认。

## 页面批准

- 评论解决、独立视觉审查通过或Agent判断可用都不等于页面确认；
- 只有Proposal Owner明确确认的版本才能进入 `deck/assembly-ready/`；
- 页面内容哈希、设计版本或资产变化时必须重开；
- 全部正式页面确认后再一次性拼装PPT/PDF。
