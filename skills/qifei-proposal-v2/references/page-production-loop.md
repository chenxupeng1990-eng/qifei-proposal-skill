# 页面路由、生产与评审Loop

## 每页生产路由

调用Image2或编写HTML前，为每张正式页记录 `presentation_route`：

- 服务对象、使用情境和演讲任务；
- 核心思想、内容关系与需要被看见的表达对象；
- 最佳载体、唯一主导类型和视觉锤；
- 首眼对象、阅读路径和最终焦点；
- Image2决策、语义角色、`visual_family_id` 和资产；
- 必须由HTML保护的文字、数据和关系；
- 视觉重量计划与孤儿元素检查。

不得先套HTML版式，再把内容和图片硬塞进去。

## Image2与HTML

- 每张正式页至少使用一个承担内容语义的已登记Image2资产；
- 场景、主视觉、机制、无文字语义图标或透明表现模块均可；
- 无关背景、装饰纹理和为了过门禁添加的角标不计入；
- 产品是场景主对象时，优先让真实产品参考与场景同光源、同透视、同接触阴影；
- Image2不生成精确正文、数据表、图表标签和需要严密核对的多步关系；
- HTML负责准确文字、数据、表格、时间线、流程和关系标注，但不能独立承担整页审美。

## 固定画布

- 导出画布固定为1920×1080、16:9；
- 浏览器响应式预览与真实导出画布分别验证；
- 检查文字裁切、换行、越界、遮挡、孤儿元素、字体替代和图片失效；
- 单页通过后检查整章montage中的视觉节奏和跨页一致性。

## 评审Loop

> 模板 → Image2核心表达 → HTML精确内容 → 固定画布QA → 整章montage → 浏览器评论 → 修改权威源 → 重建

评论循环使用HTML＋逐页PNG，或直出PNG＋Codex浏览器原生评论。修改必须回到冻结内容、页面路由、Image2源资产或HTML源文件，不直接修补最终PNG。

## 页面批准

- 评论解决、视觉QA通过或Agent判断可用都不等于页面确认；
- 只有Proposal Owner明确确认的版本才能进入 `deck/assembly-ready/`；
- 页面内容哈希、设计版本或资产变化时必须重开；
- 全部正式页面确认后再一次性拼装PPT/PDF。
