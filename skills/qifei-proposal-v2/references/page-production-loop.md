# 页面路由、生产与评审Loop

## 每页生产路由

调用Image2或编写HTML前，为每张正式页记录 `presentation_route`：

- 服务对象、使用情境和演讲任务；
- 核心思想、内容关系与需要被看见的表达对象；
- 最佳载体、唯一主导类型和视觉锤；
- 首眼对象、阅读路径和最终焦点；
- Image2决策、语义角色、`visual_family_id` 和资产；
- 必须由HTML保护的文字、数据和关系；
- 视觉重量计划与孤儿元素检查。

不得先套HTML版式，再把内容和图片硬塞进去。

## Image2与HTML

- 每张正式页以一张已登记的 Image2 整页设计底图为主体（`visual_mode: background`，`semantic_role` 为 `scene` 或 `hero`），尺寸不小于 1920×1080、比例 16:9，`validate_design_loop.py` 会检查；
- 生成底图前，先按版式定好文字区、数据区和产品位置，再写进提示词，让底图在这些区域留出干净的明暗或空间；数据页、目录页、结尾页同样有底图，只是底图更克制；
- 底图要能独立成立：去掉文字层后，它本身是一张有构图、光线和留白的完整画面，而不是纯色背景上放几张图；
- 画面铺满整页：文字区是同一场景里的留白（墙面、天空、虚化的前后景、暗部），不是空白画布。空白底上横放一条图片带、或者只在中间放几个物体、其余全是平涂底色，都不算整页底图；
- 参考图数量受工具上限约束：通常是母版 1 张加本页实际出现的产品图，总数不超过生图工具允许的张数；
- 底图的主体就是本页的最佳载体和视觉锤：数据页让比较本身成为画面，流程或循环页让关系成为空间装置，内容样张页让故事板或成品出现，产品页只出现本页讨论的产品。去掉文字后，要能看出这一页在讲什么；
- 通用氛围图不算最佳载体：同一面墙、同一机位换几句文字反复用，判为主题配图失败，退回重选载体。不同页面不得共用同一张底图；
- **按母版生图**：设计校准通过后，每类页面已确认的校准页就是这一类的母版。生成正式页底图时，把同类母版页的 PNG 和官方产品图一起作为参考图交给 Image2，要求沿用母版的版式结构、文字区位置、光线和材质，只按本页最佳载体改变画面主体。在 `image2_decision.master_reference` 登记所用母版页；
- 放在方框、卡片、缩略图里的配图，以及无关背景、装饰纹理、为过门禁加的角标，都不计入视觉底线；
- 机制图、无文字语义图标和透明PNG可以作为底图之上的补充，不能替代底图；
- 个别页面确需其他路线时，在页面上登记 `route_exception`（`record_id`、`reason`），`record_id` 必须是 Owner 对该页的批准记录；`DESIGN.md` 或校准结论不能代替；
- 产品是场景主对象时，优先让真实产品参考与场景同光源、同透视、同接触阴影；
- Image2不生成精确正文、数据表、图表标签和需要严密核对的多步关系；
- HTML负责准确文字、数据、表格、时间线、流程和关系标注，但不能独立承担整页审美。

## 固定画布

- 导出画布固定为1920×1080、16:9；
- 浏览器响应式预览与真实导出画布分别验证；
- 检查文字裁切、换行、越界、遮挡、孤儿元素、字体替代和图片失效；
- 单页通过后检查整章montage中的视觉节奏和跨页一致性。

## 评审Loop

> 模板 → Image2核心表达 → HTML精确内容 → 固定画布QA → 整章montage → 浏览器评论 → 修改权威源 → 重建

评论循环使用HTML＋逐页PNG，或直出PNG＋Codex浏览器原生评论。修改必须回到冻结内容、页面路由、Image2源资产或HTML源文件，不直接修补最终PNG。

## 页面批准

- 评论解决、视觉QA通过或Agent判断可用都不等于页面确认；
- 只有Proposal Owner明确确认的版本才能进入 `deck/assembly-ready/`；
- 页面内容哈希、设计版本或资产变化时必须重开；
- 全部正式页面确认后再一次性拼装PPT/PDF。
