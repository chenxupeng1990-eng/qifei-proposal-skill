# 提案母稿工作台合同

母稿工作台是完整提案默认的内容权威源（`content_authority: "studio"`）。它负责以下几件事：
- 把母稿渲染成适合阅读的富格式页面，导出干净的 Markdown。
- 运行本地服务时，可以在页面上直接编辑，保存即写盘，所有打开的页面实时刷新。
- 像飞书一样框选文字评论、回复、解决，Agent 也读写同一份评论。
- 让 Owner 逐章确认，并登记已核验版本，作为阶段门禁的凭证。

## 作为权威源：确认与登记（studio 项目）

- **母稿**：`content/draft/proposal-draft.md`。章节和页序登记在 `project-state.json` 的 `chapters[].slides` 里，母稿的页序必须一致。
- **确认本章**：Owner 在每章标题下点"确认"。
  - 这一章的页面必须先通过格式检查。
  - 确认会写入 `content/draft/confirmations.json`，记录确认人、时间、版本，以及每一页的内容指纹。
  - 同时会更新这一章的 `manuscript_confirmed` 和 `confirmation_record_id`。
  - 章节确认只能由 Owner 在页面上操作，Agent 不代为确认。
- **登记当前版本**：把当前母稿记为已核验版本，写入 `proposal_draft`（版本号、SHA256、页序、日志路径）。
  - 前提是格式检查 PASS，并且母稿页序和登记的页序一致。
  - 确认章节后会自动登记；有修改时，用页面顶部的按钮或 `python3 scripts/draft_studio.py register <项目目录>` 重新登记。
- **修改后自动失效**：已确认的页面一旦被修改（无论是在页面上改，还是 Agent 直接改文件），这一章就退回待确认，`proposal_draft.status` 变为 `editing`。门禁会逐页核对内容指纹，指出哪些页在确认后改过。
- **页面顶部的权威源栏**：显示登记状态和章节确认进度。全部章节都已确认、而且登记的就是最新版本时，会提示"可以进入全稿审查"。

## 阅读页与导出

- 阅读页的数据来源是项目登记的母稿：`project-state.json.proposal_draft.verified_snapshot_path`。没有登记时，依次查找 `content/draft/proposal-draft.md` 和 `content/feishu/proposal-draft.md`。
- 阅读页和导出的 Markdown 都是派生物。不能把它们登记为确认凭证，也不能反向覆盖母稿。
- 页面状态读取自 `project-state.json`：章节 `manuscript_confirmed` 显示为"已确认"，在 `verified_slide_ids` 中的页面显示为"已回读"，其余显示为"待确认"。

## 命令

在 `skills/qifei-proposal-v2/` 目录下运行：

```bash
python3 scripts/draft_studio.py render <项目目录> [--draft <母稿路径>] [--out deck/review/draft-studio.html]
python3 scripts/draft_studio.py export-md <项目目录> [--profile full|brief] [--out <文件>]
python3 scripts/draft_studio.py serve <项目目录> [--draft <母稿路径>] [--port 8765] [--open]
python3 scripts/draft_studio.py comments <项目目录> [--all] [--json]
python3 scripts/draft_studio.py reply <项目目录> <评论编号> "<回复>" [--author Agent]
node scripts/check_draft_studio.mjs <阅读页.html>
```

- `render`：生成单个 HTML 文件，可以离线打开。用 `--draft` 可以只渲染某一章的章节文件。
- `export-md --profile full`：导出全部字段。
- `export-md --profile brief`：只保留核心内容、逻辑展开、上屏内容、讲解方向和证据，适合转发和归档。
- `serve`：启动本地工作台（默认只监听 127.0.0.1），在终端打印访问地址。见下文"在线编辑与实时同步"。
- `check_draft_studio.mjs`：在无头浏览器里检查页面能否正常渲染、三种视图是否生效，并报告脚本错误。

## 母稿格式：先检查，旧稿一次性转换

母稿只有一种写法，见 [feishu-proposal-draft-format.md](feishu-proposal-draft-format.md) 2.1 节。

```bash
python3 scripts/draft_studio.py check <项目目录>            # 逐页列出格式问题，PASS 才能放行
python3 scripts/draft_studio.py normalize <项目目录>        # 只生成预览 proposal-draft.normalize-preview.md，不改原稿
python3 scripts/draft_studio.py normalize <项目目录> --write # 替换原稿，原稿备份为 proposal-draft.pre-normalize-<时间>.md
```

`normalize` 会把旧写法转成标准写法：
- 页面和章节的标题层级会被纠正。
- 加粗标签（`**核心内容：**`）和单独一行的 `**PPT上屏内容**` 会改成字段小标题。
- 别名会归入对应的字段：
  - 本页结论、本屏任务 → 核心内容
  - 建议呈现、页面呈现、建议视觉、设计思路 → 视觉生成建议
  - 事实与素材、××参考 → 证据与来源
- "品牌判断""策略结论"连同原标签放进逻辑展开；没有标签的正文也放进逻辑展开。
- 字段内的小标题改成 `####`，飞书的提示块和分栏原样保留。
- 原稿缺的字段写成"待补充"，并在报告里逐页列出。这些是需要补写的内容，不是格式问题，`check` 会一直报出来，直到补完为止。

飞书是权威源的项目，转换后的内容要回写飞书、重新回读，才能登记确认。

## 能识别的母稿写法

- 飞书回读快照：`# 章节`、`## P01｜标题`、`### 核心内容` 等字段小节，以及飞书的 `<title>`、`<callout>` 标记。
- 章节文件：`# CH02｜章节`、`## 章节说明小节`、`### [P08] 标题`，页面字段写成 `- 字段：值`。
- 其他旧写法：还没转换时，页面内容整体按"正文"显示，顶部会提示这是非标准母稿，并列出问题。
- 富格式块：`:::callout 标题`、`:::flow`、`:::compare`（两栏之间用 `---` 分隔）、`:::data`（每行写 `- 数字｜说明`），每个块以 `:::` 结束。导出 Markdown 时会转成普通引用。

## 阅读页

- 左侧是章节和页面目录，带状态；每章顶部有标题链，用来检查论证有没有断开。
- 每页按字段分区：
  - 上屏内容画成 16:9 画面示意
  - 含 `→` 的逻辑展开画成流程
  - 视觉建议画成网格
  - 策略与过桥、证据与来源默认折叠，标为"内部"
- 三种视图：
  - **完整**
  - **客户视图**：隐藏视觉、过桥和证据
  - **标题链**：只看每页标题和核心判断
- 支持搜索、下载完整或简洁 Markdown、打印。
- 需要登录才能访问的飞书图片无法加载时，显示图片说明文字代替。

## 在线编辑与实时同步（serve）

- **就地编辑**：鼠标移到字段上会出现"编辑"按钮。编辑框里是这段内容的 Markdown 源文；⌘/Ctrl+Enter 保存，Esc 取消。页面标题、章节说明也可以编辑。章节文件这类用"- 字段：值"写的页面，按整页源文编辑。
- **保存即写盘**：
  - 每次保存只替换这一段对应的源文行，原子写入母稿。
  - revision 加 1，重新计算 SHA256，把整份快照写入 `<母稿所在目录>/revisions/rev-NNNNNN.md`。
  - 在 `revisions/log.jsonl` 记录一条日志：版本、哈希、时间、修改者、涉及的页面。
  - 工作台第一次打开时，以当前文件写一条 baseline 记录，起始版本号沿用 `proposal_draft.revision_id`。
- **冲突**：保存时会核对编辑开始时的哈希。母稿已经被别处改过时返回冲突，你的文字留在编辑框里，可以选择保存到最新版本。
- **结构保护**：编辑内容不能新增、删除或重排页面；页面结构的变更走 `page-change-proposals.md` 流程。
- **外部修改**：Agent 或其他程序直接写母稿文件时，工作台在约 0.5 秒内识别到变化，记为修改者 `external` 的新版本，并推送给所有打开的页面：涉及的页面会高亮，同时提示"母稿文件被外部修改 · rev N · 页码"。所以 Agent 直接改 Markdown 即可，不需要调用接口。
- **状态**：已确认或已回读的页面一旦被编辑，状态显示为"已修改·待重新确认"。编辑前会提醒这一点。
- **安全**：
  - 服务默认只监听本机。
  - 页面内嵌一次性令牌，所有接口都要校验令牌和 Host，防止其他网页借浏览器改母稿。
- **边界**：项目选用飞书为权威源时，工作台只是阅读和编辑工具，修改要回写飞书、重新回读后才能登记确认；选用工作台（默认）时，工作台本身就是权威源。

## 评论（serve）

- **框选评论**：在正文里选中一段文字，旁边会出现"评论"按钮，点击后在右侧栏写评论。
  - 被评论的文字会以黄色高亮显示，评论卡片和原文对齐。
  - 点击高亮可以定位到对应卡片；点击卡片会滚动到原文。
- **线程**：每条评论都是一个线程，可以多人回复，Enter 发送，Shift+Enter 换行。卡片上的 ↑↓ 用来在评论之间跳转，✓ 标记解决，↺ 重新打开。
- **决定保留可见**：解决后的评论是这页的决策记录，默认仍然显示。
  - 原文用绿色虚线标出，卡片折叠成一行"✓ 已决定"，并列出最初的问题和最后的结论；点开可以看完整讨论。
  - 同一时间只有一张卡片处于选中状态。点卡片或原文高亮会选中并展开；点卡片上的"收起"、按 Esc，或点正文空白处，都会取消选中并折回。
  - 超过 5 行的单条消息先截断，点"展开全文"可以看完整内容。
  - 右侧栏顶部可以在"全部 / 未解决 / 已决定"之间切换。
  - 页面标题旁的绿色 ✓ 计数，是这页已决定的意见数。
- **导出**：完整版 Markdown 会在每页末尾附上"评审记录"，列出每条意见的引文、全部讨论和由谁决定；简洁版不带评审记录。
- **快捷同意**：一条未解决的评论，如果最后一句是别人说的（比如 Agent 的回复），卡片上会出现"✓ 同意并解决"和"同意"两个按钮：前者回复"同意。"并同时标记解决，后者只回复"同意。"、评论保持打开，适合还要等 Agent 落实修改的情况。
- **评论栏收起后**：屏幕右侧边缘会出现一个竖排的"评论"标签，显示未解决数，点一下就能重新展开。
- **计数**：页面标题旁和左侧目录用黄色显示每页未解决的评论数，点击会跳到这一页的第一条评论。
- **存储**：评论保存在母稿同目录的 `comments.json`。每条评论记录页面、字段锚点（如 `P09:core`）、引文及前后文、状态、创建时的母稿版本，以及全部回复。引文找不到时，原文可能已经改过，卡片会提示"原文已修改，找不到引用位置"。
- **Agent 的做法**：
  1. 用 `comments` 列出未解决的评论。
  2. 修改母稿：直接写 Markdown 文件，工作台会实时同步。
  3. 用 `reply` 回复说明改了什么、在哪个版本。
- **谁关闭评论**：Agent 不关闭评论，由 Owner 在页面上决定是否解决。
- **实时**：网页上新增、回复、解决评论，以及 Agent 写入 `comments.json`，都会实时推送到所有打开的页面，并提示是谁回复了哪一页。
- **署名**：评论默认署名 Owner，可以在右侧栏顶部修改，署名保存在本机浏览器。
- **窄屏**：窗口较窄时，评论栏改为右侧抽屉，从顶部的"评论"按钮打开。
